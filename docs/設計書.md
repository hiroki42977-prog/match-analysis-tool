# 試合分析ツール 設計書（フェーズ1）

作成日: 2026-10-13
元にした資料: `match-analysis-tool-requirements.md`（要件定義書）
この設計書は、要件定義書をもとに、ひろきさんとの確認で決めた内容をまとめたもの。要件定義書と違うところは「要件定義書からの変更」に書いた。食い違うときは、この設計書を正とする。

---

## 1. 目的と完成の条件

- 目的: 選手1人ずつに、プレーの数字（スタッツ）を返して、フィードバックに使う。
- 使う人: ひろきさん（iPadで記録・集計）、選手（iPhoneなどでスプレッドシートのレポートを見る）。
- 一番大事なこと: 記録の手数を最小にする。記録は映像を見る時間で終わり、レポートはボタン1つで出す。
- **完成の条件**: 1人の選手を1試合分最後まで記録し、「レポート作成」で作ったスプレッドシートを iPhone で開いて、表・レーダーチャート・矢印マップが正しく見られること。

## 2. 確認で決まったこと

| 項目 | 決定 |
| --- | --- |
| 記録する端末 | iPad（Safari）。ホーム画面に追加して使う |
| 記録画面の配置 | A案: 左に映像、右に操作 |
| 追う選手 | 記録は1人の選手を追う形。選手は記録を始める前に1回選ぶ（途中で変更可） |
| ピッチ図 | リアルなピッチ（センターサークル・ペナルティエリア・ゴールエリア・ゴール）に、ゾーンの区切りを点線で重ねる。横向きで、右が攻める向き |
| レーンの区切り | 5等分 |
| ゾーンの向き | 前半・後半とも「自チームが攻める向き」を基準にする（列6が相手ゴール側）。レーンの左右も攻める向きから見る |
| 前半・後半 | 記録画面の切り替えボタンで、ひろきさんが切り替える |
| シュートの表 | 枠外(L) の行も作る |
| シュートのゾーン | 打った場所を `startZone` に入れる |
| スプレッドシートへの書き込み | Google Apps Script を受け取り係にする（ひろきさんの普段の Google アカウントに設置） |
| 書き込みのタイミング | 2段構え。記録のたびに「記録一覧」へ1行追加し、「レポート作成」ボタンで選手ごとのレポートを作る |
| 選手のスプレッドシート | 選手1人につき1ファイル。試合ごとにタブを増やす。選手は本人のファイルだけ見られる |
| 公開先 | GitHub Pages |
| 映像からの自動検知 | 今回は作らない。フェーズ3で、Mac 上で1〜2分の映像を使って試す |

## 3. 要件定義書からの変更

1. **選手ボタンをなくした**（要件 4.2・4.3）: 記録画面に選手ボタンを並べず、追う選手を1人だけ表示する。1件の記録は最大5タップ → 最大4タップになる。
2. **スプレッドシートへの転記を2段構えにした**（要件 4.2・4.3）: 記録のたびに転記するのは「記録一覧」（1件1行）。見本と同じレイアウトのレポートは「レポート作成」ボタンで作る。1件ごとにレポート全体を作り直すと、送るたびに数秒かかり、電波が弱いと止まるため。
3. **選手のスプレッドシートの単位を決めた**（要件 4.5 の【仮定】）: 選手1人1ファイル、試合ごとに「スタッツ」「マップ」の2タブを足す。
4. **レポートの2ページ目に、ヒートマップの画像も入れる**（要件 4.4・4.5）: 矢印マップ（パス・ドリブル）に加えて、守備とシュートのヒートマップも載せる。守備は矢印を出さないため、選手が自分の守備の場所を見られるのはこの図だけになる。

## 4. 画面

| # | 画面 | 内容 |
| --- | --- | --- |
| 1 | ホーム | 試合の一覧（新しい順）、「新しい試合」ボタン、名簿・設定への入口 |
| 2 | 名簿 | チームを作り、背番号と名前を登録する。チームごとに1回登録すれば使い回せる |
| 3 | 試合の登録 | 日付・対戦相手・11人制／8人制・YouTube のリンク・出場選手（名簿から選ぶ） |
| 4 | 選手を選ぶ | 試合を開くと出場選手が並ぶ。追う選手を1人選ぶと記録画面へ。各選手の記録件数も出す |
| 5 | 記録画面 | 下の「5. 記録画面」 |
| 6 | 記録一覧 | 追っている選手の記録を時間順に並べる。行を押すと映像がその場面へ飛ぶ。直す・消すができる |
| 7 | 結果 | 選手ごとの集計表、ヒートマップ（プレー種類で切り替え）、矢印マップ、チーム全体の比較表、CSV 書き出し、「レポート作成」ボタン |
| 8 | 設定 | Apps Script の URL と合言葉を入力する（iPad に1回だけ） |

画面の見た目は、シンプルで押し間違えにくいことを優先する。ボタンは指で押しやすい大きさ（最低 44×44pt）にする。

## 5. 記録画面

### 配置（iPad 横向き）

- **左（約52%）**: YouTube の映像。下に操作ボタン（10秒戻る・再生／一時停止・倍速の切り替え 1倍→1.5倍→2倍・前半／後半の切り替え）。その下に「直前の記録」（最新3件）と送信の状態（例: 「未送信 3件」）。
- **右（約48%）**:
  - 上: 追っている選手（例: 「#10 山田 太郎」）、この選手の記録件数、「選手を変える」ボタン
  - 中: プレーのボタン（4列×3段）
    - パス／レガーテ／コンドゥクシオン／プロテクション
    - ボール奪取／1対1／空中戦／**失敗**
    - 枠内R／枠内L／枠外R／枠外L
  - 下: ピッチ図（30マス）。いま何を押す番かを、ピッチの上に一言で出す（例: 「パス ― 始点ゾーンを押してください」）

確定したイメージ図: `docs/イメージ図/記録画面.html`

### 入力の流れ

| プレー | 押す順番 | タップ数（失敗なし／あり） |
| --- | --- | --- |
| パス・ドリブル | プレー → （失敗）→ 始点 → 終点 | 3／4 |
| 守備 | プレー → （失敗）→ 場所 | 2／3 |
| シュート | 枠内R などのボタン → 打った場所 | 2（成功・失敗はボタンで決まる） |

- 成功／失敗は、初期値が「成功」。「失敗」はプレーを選んだあと、最後のゾーンを押す前ならいつでも押せる（もう一度押すと成功に戻る）。1件保存したら「成功」に戻る。
- 最後のゾーンを押した瞬間に1件保存する。確認の画面は出さない。
- 再生位置は、**プレーのボタンを押した瞬間**の位置を保存する（プレーが起きた場面に一番近いため）。
- 記録中も映像は止めない。
- 途中でやめたいときは、選んでいるプレーのボタンをもう一度押すと解除できる。
- 保存した直後、「直前の記録」の一番上に、取り消しボタンを出す。パスの場合は「前／横／後ろ」の判定結果を出し、押すとその場で直せる（`passDirectionOverride` に入る）。

### 選手ごとの続き

同じ試合で別の選手を追うときは、映像をもう一度見る。そのため、選手ごと・試合ごとに「最後に見た再生位置」と前半／後半を覚えておき、次に開いたときはその続きから始める。

## 6. 判定と集計のルール

要件定義書の「5. 判定ルール」をそのまま使う。集計の計算は1か所にまとめ、画面の表示・CSV・スプレッドシートのすべてが同じ計算を使う。

- パスの向き: `diff = endCol - startCol`。正なら前、0なら横、負なら後ろ。`passDirectionOverride` があればそちらを使う。
- 成功率: `成功数 / (成功数 + 失敗数)`。分母が0なら空欄（0% にしない）。
- シュート: 枠内が成功、枠外が失敗。
- レーダーチャートの4軸: パス・ドリブル・守備の成功率、シュートの枠内率。前半・後半で別々に出す。

## 7. データ

要件定義書の「6. データモデル」をそのまま使う（Team / Player / Match / PlayEvent）。次の2つを足す。

- **PlayerProgress**（選手ごとの続き）: `matchId`, `playerId`, `videoTimeSec`, `half`
- **SyncQueue**（未送信の記録）: 送る内容（追加・変更・削除）、作った日時、失敗した回数

`subtype` の値は要件定義書と同じ。パスの `subtype` は保存のときに自動判定で入れ、手で直したら `passDirectionOverride` に入れる。

### iPad の中への保存

- IndexedDB（ブラウザの中にあるデータの保管場所）に、押すたびすぐ保存する。
- Safari の「7日間使わないサイトのデータを消すことがある」仕組みを避けるため、ホーム画面に追加して使う。完成時に追加の手順を案内する。
- 控えとして、記録はスプレッドシートの「記録一覧」にも残る。CSV でも書き出せる。

## 8. スプレッドシート連携

### 受け取り係（Google Apps Script）

- ひろきさんの Google アカウントに、Web アプリとして1回だけ設置する。ツールからの送信を受け取り、Google ドライブの「試合分析」フォルダの中にファイルを作る・書き込む。
- 送るたびに合言葉を付け、合っているときだけ受け付ける。URL と合言葉はプログラムには書かず、設定画面で iPad に入力する（プログラムは GitHub で公開されるため）。
- プログラムは `apps-script/` フォルダに置く。設置の手順書も同じフォルダに置く。

受け付ける操作:

| 操作 | 内容 |
| --- | --- |
| 記録の追加・変更 | 「記録一覧」に1行追加する。同じ ID の行があれば書き換える |
| 記録の削除 | 同じ ID の行を消す |
| レポート作成 | 選手1人分のレポートを作る（下記） |

### 記録一覧（1ファイル）

ファイル名「試合分析 記録一覧」。1件1行で、列は次のとおり。
記録ID / 試合日 / 対戦相手 / 形式 / 前後半 / 背番号 / 名前 / プレー / 種類 / 足 / 成功 / 始点レーン / 始点ゾーン / 終点レーン / 終点ゾーン / 向きの手修正 / 再生位置（秒）/ 映像リンク（その場面から再生できるリンク）/ 記録日時

### 送信の仕組み

- 記録は、まず SyncQueue に入れてから送る。送れたら SyncQueue から消す。
- 電波がないとき・失敗したときは残しておき、つながったら古い順に自動で送り直す。
- 記録画面に未送信の件数を出す。0件なら「送信済み」と出す。

### 選手のレポート（選手1人1ファイル）

- ファイル名: 「#背番号 名前（チーム名）」。最初の「レポート作成」で作り、2回目からは同じファイルにタブを足す。
- タブ名: 「10/13 vs ◯◯ スタッツ」「10/13 vs ◯◯ マップ」。同じ試合でもう一度「レポート作成」を押したら、その2タブを作り直す。
- 「レポート作成」ボタンは、結果画面で試合を選んで押す。その試合で記録がある選手全員分をまとめて作る。

**スタッツのタブ**（見本と同じレイアウト。分析官・アシスタント・得点者・アシスト者の欄は作らない）

| ブロック | 表 |
| --- | --- |
| レーダーチャート | 前半・後半を別々のチャートで並べる。4軸（パス・ドリブル・シュート・守備） |
| パス | 「成功」「失敗」「成功率」の3つの表を横に並べる。行: 前／横／後ろ／合計、列: 前半・後半 |
| ドリブル | 同じ形。行: レガーテ／コンドゥクシオン／プロテクション／合計 |
| 守備 | 同じ形。行: ボール奪取／1vs1／空中戦／合計 |
| シュート | 「成功」「失敗」の2つの表。行: 枠内(R)／枠内(L)／枠外(R)／枠外(L)。成功の表に枠内、失敗の表に枠外の数を入れる |

**マップのタブ**

ツールの中で画像（PNG）を作って送り、貼り付ける。前半・後半を合わせた1試合分。

- 矢印マップ: パス（成功は実線、失敗は破線）、ドリブル（太い矢印）
- ヒートマップ: 守備、シュート（30マスごとの本数と成功率を色の濃さで表す）

### 選手への共有

ひろきさんが、選手のファイルの「共有」ボタンから選手に共有する。ツールからは共有しない。1ファイルに試合が足されていくので、共有は最初の1回だけで済む。

## 9. 結果画面（ひろきさん用）

- 選手を選ぶと、その選手の集計表（パス・ドリブル・守備・シュート × 前半・後半・合計）を出す。
- ヒートマップ: プレー種類（パス・ドリブル・守備・シュート）で切り替える。30マスごとに本数と成功率を出し、色の濃さで表す。
- 矢印マップ: パス・ドリブル。
- チーム全体: 選手を1行ずつ並べ、各プレーの本数と成功率を比べる表。
- 「CSV 書き出し」ボタン: その試合の全記録を CSV で保存する。
- 「レポート作成」ボタン。

## 10. 作り方

- iPad の Safari で動く Web アプリ（PWA：ホーム画面に追加してアプリのように使えるもの）。横向きが前提。
- Vite ＋ TypeScript。画面を作るための大きな部品（フレームワーク）は使わず、軽くする。
- 映像: YouTube IFrame Player API。`getCurrentTime()` で再生位置を取る。
- ピッチ図・ヒートマップ・矢印マップ: SVG で自前で描く。スプレッドシートに貼る画像は、同じ図を PNG に変換して作る。
- 公開: GitHub Pages。GitHub に保存すると、自動で新しい版に置き換わるようにする。

### 部品の分け方

| 部品 | 役割 |
| --- | --- |
| 判定・集計 | パスの向きの判定、成功率、各表の数字。画面にもスプレッドシートにも依存しない |
| 保存 | IndexedDB への読み書き |
| 送信 | SyncQueue と Apps Script への送信 |
| 映像 | YouTube プレーヤーの操作 |
| ピッチ描画 | ピッチ図・ヒートマップ・矢印マップの SVG と PNG |
| 画面 | 4章の各画面 |
| Apps Script | 受け取り、記録一覧の書き込み、レポートの作成 |

## 11. 確認の方法

1. **計算の自動テスト**: パスの向き（前・横・後ろ、手修正あり）、成功率（分母0は空欄）、各表の数字、シュートの成功・失敗を、テスト用のプログラムで確かめる。
2. **画面の確認**: Mac 上で、Safari と同じ仕組み（WebKit）を使い、iPad の横向きの画面サイズで記録の流れを最後まで操作して確かめる。
3. **スプレッドシートの確認**: 試しのデータで「レポート作成」を押し、表・レーダーチャート・マップが見本どおりにできるかを見る。
4. **実機の確認**: iPad（記録画面）と iPhone（選手が見るスプレッドシート）で、ひろきさんに確かめてもらう。Chrome だけの確認では「完了」にしない。
