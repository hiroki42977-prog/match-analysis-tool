# 設計書：出力の見た目を見本（見本フォルダの写真）に合わせる

作成日：2026-10-19
対象：試合分析スタッツツール（結果画面の図・PDF・レポート入力）

## なぜ変えるか

- コーチが選手に渡している資料（見本フォルダの IMG_1416〜1419）と、ツールの出力の見た目が違う。見本に限りなく近づけたい。
- 印のルールは、手書きのメモ（IMG_1425）に合わせる。
- 見本の2ページ目にある「コメント」「評価」「コンディション」などは今のツールでは記録していないので、iPad で入れられるようにする。
- このツールは試合のスタッツを入れるためのもの。ここに書いたこと以外の機能は足さない。

## 作らないもの

- フォーメーション図
- 戦術項目の表と「戦術」のレーダーチャート
- 見本のロゴ（FA・PROTRAINUP）。ロゴの場所にはチーム名を文字で入れる
- 次節の課題の赤字の一言（見本の「※もう一週同じパフォーマンスが見たい！！」）
- 印をマスの中の好きな場所に置くこと（記録はマス単位のまま）

## ① ピッチの図（1st・2nd）

### 見た目

- 白地に黒い線。縦向きで、上が相手ゴール。斜め上から見たように奥（上）ほど細くなる台形にする。
  - 上の辺の幅は、下の辺の幅の 0.55 倍（見本の写真から測った値）。
  - 平らなピッチを台形に写す計算（射影変換）で描くので、奥のマスほど縦も短くなる。
- ピッチの線：外枠、ハーフウェーライン、センターサークル、ペナルティエリア、ゴールエリア、ペナルティアーク、ゴール。すべて黒の実線。
- マスの線：黒の破線。縦の破線4本（5レーン）、横の破線4本（6列。真ん中はハーフウェーラインの実線）。
- レーン1（左サイド）は左、列6（相手ゴール側）は上。
- 図の左上に「1st」または「2nd」の文字。図の中に凡例は入れない。

### 印（手書きメモ IMG_1425 のとおり）

| プレー | 成功 | 失敗 | 置く場所 |
|---|---|---|---|
| パス | 緑の矢印 | 赤の矢印 | 始点のマス → 終点のマス |
| コンドゥクシオン | 青の波線の矢印 | 赤の波線の矢印 | 始点のマス → 終点のマス |
| レガーテ | 青い丸に「L」 | 赤い丸に「L」 | 始点のマス |
| プロテクション | 青い丸に「P」 | 赤い丸に「P」 | 始点のマス |
| ボール奪取 | 黒いサッカーボール | 赤いサッカーボール | 記録したマス |
| 1対1 | 青い丸に「1」 | 赤い丸に「1」 | 記録したマス |
| 空中戦 | 青い丸に「空」 | 赤い丸に「空」 | 記録したマス |
| シュート | 黒の「○」（枠内） | 黒の「×」（枠外） | 打ったマス。線は引かない |

- 丸の印は、白い中に色のふちと色の文字（見本と同じ）。
- 線は細く、矢じりは小さく、始点の●は付けない。
- 同じマスに印や始点がいくつもあるときは、今と同じくマスの中に散らして並べる。
- 印の大きさは画面上で同じ大きさにする（奥でも小さくしない）。

### 使う場所

- 結果画面：今の7枚の図（全体マップ前半・後半、パス、ドリブル前半・後半、守備、シュート）を、1st・2nd の2枚に置き換える。
- PDF：1ページ目に2枚。
- スプレッドシートのレポート：貼る画像も 1st・2nd の2枚にする。Apps Script は画像を横長（113:76）の大きさで貼るので、白い横長の画像の真ん中に縦のピッチを置いて送る。Apps Script の入れ直しはしない。
- 変えないもの：記録画面のピッチ、結果画面の「場所ごとの本数」の図、集計の表、チーム全体の表（今の緑の図のまま）。

## ② レポート入力画面（新しく作る）

### 入り方

- 結果画面のボタンの並びに［レポート入力］を足す。押すと、今選んでいる選手の入力画面を開く。
- 画面のアドレス：`#/match/:id/report/:playerId`
- 入れたものは、文字を打つたびに iPad の中に保存する（保存ボタンは置かない。入れ忘れて消えることを防ぐ）。
- 上に［← 結果に戻る］。

### 入れる項目

試合ごと（同じ試合のどの選手の画面から入れても同じ値）

- スコア：前半（自チーム・相手）、後半（自チーム・相手）。合計は自動で出す
- 試合条件、試合時間、試合会場、キックオフ時間、天候、ピッチコンディション
- システム（自チーム）、システム（相手）
- 相手のエンブレム画像

選手ごと

- Pコンディション、Mコンディション
- 評価（前半）、評価（後半）
- 出場ポジション、出場時間
- 個人テーマ（攻撃）、個人テーマ（守備）
- 分析者、得点、アシスト
- コメント（何行でも）
- 次節の課題（攻撃）、次節の課題（守備）

一度入れれば次から使い回すもの

- 選手の顔写真（選手ごと）
- 自チームのエンブレム（チームごと）

- 文字の項目はすべて自由に打てる欄にする（選択肢にはしない）。
- 画像は iPad の写真から選ぶ。保存の前に長い辺 600px の JPEG に縮めて、iPad の保存場所を圧迫しないようにする。画像には［消す］も付ける。

### データの形

- 新しい保存場所を2つ足す（iPad の中のデータベースの版を 1 → 2 に上げる）。
  - `matchReports`（試合ごと、キーは試合の id）
  - `playerReports`（試合×選手ごと、キーは [試合の id, 選手の id]）
- `Player` に `photo?: string`、`Team` に `emblem?: string`（縮めた画像のデータ）を足す。
- 今までの記録・試合・選手は1件も消さず、そのまま読めること。

## ③ PDF（A4縦・選手1人につき2ページ）

- 今の［PDF 書き出し］→［PDF を保存］の2段階はそのまま。ファイル名も今のまま（`日付_vs_相手_#背番号名前.pdf`）。
- 今の「A4横・図1枚につき1ページ」はやめて、下の2ページにする。
- 日本語の文字は、今と同じくページ全体をキャンバスに描いてから PDF に貼る。細かい表の文字がつぶれないよう、約200dpi（1654×2339px）で描く。
- 入っていない項目は空欄のまま出す（「未入力」などの文字は出さない）。

### 1ページ目

1. いちばん上の真ん中：チーム名
2. 「1st」の図
3. 「2nd」の図
4. 「コメント」の表：灰色の見出しの帯、下に枠。文字は真ん中ぞろえ
5. 「次節の課題」の表：灰色の見出しの帯、下に2行（「攻撃:…」「守備:…」）

### 2ページ目

1. 右上：日付（例：2026年9月22日）。上の真ん中：チーム名
2. 顔写真、自チームのエンブレム「vs」相手のエンブレム、【スコア】（1st・2nd・Total）
3. 情報の表（濃い灰色の見出しのマスと白い値のマス、2列ずつ）
   - 左：名前、Pコンディション、Mコンディション、評価1st、評価2nd、出場ポジション、出場時間、個人テーマ（攻撃）、個人テーマ（守備）、分析者
   - 右：試合条件、試合時間、試合会場、キックオフ時間、天候、ピッチコンディション、システム、相手システム、得点、アシスト
4. レーダーチャート2つ（「前半」「後半」）。4つの軸は上＝パス、右＝ドリブル、下＝守備、左＝シュート。目盛りは 0〜100% を 20% ごと。前半は水色、後半は緑で塗る
5. 数字の表（IMG_1417 の上半分）：パス・ドリブル・守備・シュートの4つ
   - 濃い灰色の帯に水色の文字で「パス成功率」などの見出し
   - 列：成功（前半・後半）、失敗（前半・後半）、総数（前半・後半）、成功率（前半・後半）
   - 行：パス＝前・横・後・合計、ドリブル＝レガテ・コンドゥクシオン・プロテクシオン・合計、守備＝ボール奪取・1vs1・空中戦・合計、シュート＝枠内(R)・枠内(L)・枠外(R)・枠外(L)・合計
   - 成功率は「57%」のように丸める。分母が0のときは「-」

## 確かめ方

- 自動テスト
  - 台形への写し方：四隅とハーフウェーラインの位置が正しいこと
  - 印：手書きメモの表のとおりの形・色・文字になること（成功・失敗の両方）
  - 古いデータ（版1）を開いても、記録・試合・選手がそのまま読めること
  - レポートの入力が保存され、開き直しても残っていること。試合ごとの項目は別の選手の画面でも同じ値になること
  - 数字の表の値が、今の集計と一致すること
- 見た目の確認：結果画面と PDF の2ページを撮影し、見本の写真と並べて比べる
- 実機の確認（ひろきさんにお願いする）：iPad のホーム画面のアプリで、写真を選べること、PDF を保存できること、文字が欠けていないこと
