# スプレッドシート出力を手書きの設計図の形にする 設計書

作成日：2026-10-22（同日、見本で確かめた内容に更新）
参考：フォルダ直下の手書きの設計図 IMG_1487.JPG（1ページ目）・IMG_1488.JPG（2ページ目）。git には入れない。
見本：ひろきさんの Google ドライブの「見本_スプレッドシート出力」（Excel から変換したもの）。作り方は .superpowers/mock/（git には入れない）。

## 目的

選手に渡す正式な資料を Google スプレッドシートにする。PDF が要るときはスプレッドシートから書き出す。
ツールが数えた数字・図はツールが入れ、ひろきさん以外の担当者が書く欄は空けておき、そのままスプレッドシートに書き込めるようにする。

## ひろきさんが決めたこと

- 出力はスプレッドシートを正とする。PDF はスプレッドシートから書き出す。ツールの PDF ボタンは今回は触らない（残す）。
- ファイルは今と同じく選手ごとに1ファイル。
- 1ページ目のレーダーチャートより上（チームロゴ・写真・〇 vs 〇・スコア・名前などの項目・ポジション図）と、2ページ目のコメント・次節の課題は、ひろきさんが埋める場所ではない。ツールは枠と項目名だけ作って空けておく。
- 表の中身は、これまでツールで数えていたものと同じ。
- 枠も表もツールが毎回組み立てる（ひな形のスプレッドシートは使わない）。
- 見本で決めた見た目：
  - 項目名・見出しは、成功率の表と同じ配色（濃い灰色 #4a4a4a の地にミント色 #6fe3cf の文字）。
  - いちばん上の真ん中に、チームロゴを貼る空欄（左上に薄い字で「チームロゴ」）。
  - ポジション図は、横向きの緑のグラウンド（白い線）を右上に大きく置く。担当者が選手の位置を描き込む。
  - プレーマップ 1st・2nd は緑のグラウンド（白い線）。成功したパスの矢印は白。凡例の行も緑の地に白い文字。
  - レーダーチャートは前半（水色）・後半（緑）・全体（オレンジ #f39c12）の3つ。
  - 印刷設定「A4・縦・幅に合わせる・余白は標準」で、ちょうど2ページ。下の余白は上の余白と同じくらい。
  - 2枚目のプレーマップの図にも、左右と下の枠線が見える。

## タブの形

- 試合ごとに1タブ。名前は「M/D vs 相手」（例：`10/19 vs ◯◯`）。
- 前の版で作った「◯◯ スタッツ」「◯◯ マップ」のタブは消さずに残す。新しいファイルを作ったときだけ、最初からある空のシートを消す（今と同じ）。
- 列は A〜J の10列、どれも幅 72px（合計 720px）。グリッド線は隠す。
- 1ページ目は 1〜53 行目、2ページ目は 54〜61 行目。

## 空けておく欄

- セルをつなげて書き込み欄にし、細い罫線（#555555）で囲む。
- 文字は折り返して表示し、左上に詰める。

## 送り直したときに書き込みを消さない

- その試合のタブがまだ無いとき：タブを作り、列幅・行の高さ・枠・項目名・ポジション図・ツールの中身を全部入れる。
- その試合のタブがもうあるとき：タブは作り直さない。表の範囲（A22:J53）の中身を消して書き直し、ツールが貼った画像（レーダー・プレーマップ・凡例）だけを貼り直す。
  - ツールが貼った画像には目印（代替テキストのタイトルが `tool:` で始まる）を付けておき、その画像だけ消す。ポジション図には `frame:` を付け、送り直しでは触らない。
  - 担当者が書いた文字・貼った写真や図はそのまま残る。

## 変えるところ

- アプリ側
  - ピッチの図と凡例を緑のグラウンドでも描けるようにする（PDF は今の白地のまま）。
  - ポジション図（横向きの緑のグラウンド）と、プレーマップの見出し付きの画像を描けるようにする。
  - レーダー図を「全体」でも描けるようにする。
  - 送る中身を、新しいタブの形（列幅・行の高さ・枠・表・画像の置き場所）にして送る。
- Apps Script 側（apps-script/Code.gs）
  - 送られた形どおりにタブを組み立てる処理と、既にあるタブのツールの場所だけ書き換える処理に置き換える。
  - 動作確認用の selfTest を新しい形に合わせる。
  - 設置手順.md に、貼り替えの手順と PDF の書き出し方（ファイル → ダウンロード → PDF → 用紙 A4・縦・幅に合わせる・余白は標準）を書く。

## 確かめること

- アプリ側の自動テスト：送る中身（タブ名・行の高さの合計・表の数字・全体のレーダーの値・画像の数と置き場所）が正しいこと。
- Apps Script 側：Google の外で、まねの部品を使って Code.gs を動かし、新しいタブでは全部入ること、送り直しでは担当者の文字・画像が残りツールの画像だけ入れ替わることを確かめる。
- ひろきさんに、Apps Script の貼り替え → selfTest の実行 → iPad から送信、をしてもらい、次を見てもらう。
  - 見本と見比べて形が合っているか
  - 印刷設定で「合計：2ページ」になり、下の余白が上と同じくらいか
  - 空けておく欄に文字を入れてから送り直し、文字が残るか
- それまでは「実機では未確認」とする。

## 気をつけること

- Apps Script には改ページの位置を決める機能が無い。行の高さで1ページの大きさを合わせている。見本（Excel から変換）と本番（ツールが直接作る）で入り方が少し違う場合は、行の高さの数字を1か所で直せるようにしておき、本番で確かめて合わせる。
- 余白を「広い」にするなど印刷設定を変えると、3ページになることがある。書き出しの手順には「余白は標準」と書く。
- Apps Script を書き換えたら、ひろきさんに貼り替えてもらうまで新しい形は出ない。古い受け取り係に送ったときは「受け取り係の貼り替えが必要です」と分かる言葉を出す。
- 画像は大きすぎると Apps Script で貼れないので、1枚 100万画素より小さくする。
