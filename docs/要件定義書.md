# 試合分析ツール 要件定義書（Claude Code 用）

作成日: 2026-10-13 / 作成者: コーチ（ユースサッカーコーチ）

このファイルは、Claude Code（VS Code）で実装するための要件定義書。実装前に最後まで読み、「5. 判定ルール」「6. データモデル」を仕様の正とすること。
「【仮定】」と書いた箇所は、依頼者から明確な指示がなく、設計上の都合で置いた前提。実装前に依頼者へ確認してよい。

---

## 1. プロジェクト概要

| 項目 | 内容 |
| --- | --- |
| 目的 | 選手への個人フィードバック（個人分析用） |
| 利用者 | コーチ（記録・集計）、選手（レポートを見る） |
| 対象の試合 | 11人制（中学以上）、8人制（小学生） |
| 映像 | 手持ちで追いかけ撮影したもの。YouTube のリンクで受け取り、ツール内で再生する |
| 記録する人・端末 | コーチがタブレットで記録する |
| 方式 | 半自動（映像を見ながら手で記録 → 集計・レポートは自動）。将来は自動検出を足す |
| 記録する対象 | 自チームの選手のプレーのみ。相手チームのプレーは記録しない |

### 設計の最優先事項

スタッツを出す作業は毎回繰り返す面倒な作業なので、**操作の手数を最小にする**。記録は映像を見る時間で終わり、レポートはボタン1つで出ることを目標にする。

---

## 2. 記録するプレー

記録するプレーは、パス・ドリブル・守備アクション・シュートの4種類。

| プレー | 種類 | 成功の定義 |
| --- | --- | --- |
| パス | 前 | 味方に届いたら成功 |
| パス | 横 | 味方に届いたら成功 |
| パス | 後ろ | 味方に届いたら成功 |
| ドリブル | レガーテ（相手を抜く） | ボールを失わなかったら成功 |
| ドリブル | コンドゥクシオン（スペースへ運ぶ） | ボールを失わなかったら成功 |
| ドリブル | プロテクション（ボールを守る） | ボールを失わなかったら成功 |
| 守備アクション | ボール奪取 | ボールを奪えたら成功 |
| 守備アクション | 1対1（見本の表記は「1vs1」） | ボールを奪えたら成功、または抜かれなかったら成功（どちらかを満たせば成功） |
| 守備アクション | 空中戦 | 競り勝って、先にボールに触れたら成功 |
| シュート | 枠内／枠外 × 利き足（R・L） | 枠内なら成功、枠外は失敗 |

- ドリブルは3種類とも「失ったら失敗、失わなかったら成功」で統一する。
- シュートの R・L は利き足（R＝右足、L＝左足）。例: 枠内(R)、枠内(L)、枠外(R)。枠外(L)も同じ規則で扱う。【仮定】見本画面では枠外(L)の行が見えていない。

---

## 3. ゾーン定義

ピッチを **5レーン × 6ゾーン = 30マス** に分ける。11人制・8人制とも同じ割り方。

- ゾーン（列）: 1〜6。ゾーン1が自陣ゴール側、ゾーン6が相手ゴール側。ゾーン3と4の間がハーフウェーライン。
- レーン（行）: 5つ。左サイド / 左ハーフスペース / 中央 / 右ハーフスペース / 右サイド。
- 【仮定】ゾーンは常に「自チームが攻める向き」を基準にして記録する（前半・後半でピッチの向きが入れ替わっても、列の番号は変えない）。レーンの左右も、攻める向きから見た左右とする。

座標の表し方: `{ lane: 1〜5, col: 1〜6 }`（lane 1 = 左サイド、lane 5 = 右サイド、col 1 = 自陣ゴール側、col 6 = 相手ゴール側）。

## 4. 機能要件

### 4.1 入力（映像）

| 項目 | 内容 |
| --- | --- |
| 受け取るもの | YouTube の試合映像リンク（メール等で送られてくる） |
| 再生 | リンクをツールに貼ると、タブレット画面でその映像を再生できる |
| 試合情報 | 日付・対戦相手・11人制／8人制・出場選手を登録する |
| 記録との紐づけ | 各プレー記録に、映像リンクと再生位置（時刻）を保存する |

### 4.2 記録画面

タブレットの横画面で、YouTube の再生画面と記録ボタンを並べて使う。

| 要件 | 内容 |
| --- | --- |
| 映像の読み込み | YouTube のリンクを貼ると、画面内で再生できる |
| 入力の流れ | 選手 → プレー種類 → 成功／失敗 → 始点ゾーンをタップ。パス・ドリブルは終点ゾーンもタップ。最大で5タップで1件 |
| プレー種類 | パス、レガーテ、コンドゥクシオン、プロテクション、ボール奪取、1対1、空中戦、シュート（枠内/枠外 × 利き足）をボタンで選ぶ。パスの前・横・後ろは選ばない（5.1で自動判定） |
| ゾーン入力 | ピッチ図（5レーン×6ゾーン）を直接タップ |
| 時刻 | タップした瞬間の再生位置を自動で保存 |
| 修正 | 直前の記録を取り消す。一覧から編集できる |
| 選手名簿 | チームごとに背番号と名前を登録しておき、試合ごとに出場選手を選ぶ |
| 試合形式 | 11人制／8人制を切り替えられる（ゾーン割りは共通） |
| 保存 | タブレット内に自動保存し、途中で閉じても続きから再開できる。同じ記録を、見本と同じレイアウトで Google スプレッドシートにも自動で入力する（タブレット内とスプレッドシートの両方に保存できるのが理想） |

### 4.3 工数を減らす設計（必須）

| 作業 | 減らす工夫 |
| --- | --- |
| 選手の選択 | 試合前に出場選手を登録しておき、記録中は選手ボタンを常に画面に並べて1タップで選ぶ。選手名簿はチームごとに1回登録すれば使い回せる |
| 成功／失敗 | 初期値を「成功」にして、失敗のときだけ「失敗」を押す |
| パスの前・横・後ろ | 始点と終点のゾーンから自動で判定する。違うときだけ手で直す |
| 映像の操作 | 倍速再生、10秒戻るボタン、タップした瞬間の時刻を自動保存 |
| 記録する範囲 | 分析したい選手だけを記録できる（全員を記録しなくてよい） |
| 集計 | 本数・成功率は手計算せず、記録から自動で集計する |
| スプレッドシートへの保存 | 記録するたびに自動で転記し、手でコピーしない |
| レポート作成 | 記録を終えたら、ボタン1つで全選手の個人レポートとヒートマップを作る |

### 4.4 出力

出力は「選手別の個人レポート」と「ゾーン別のヒートマップ（矢印マップ）」。選手がスマホで開ける形にする。

| 出力 | 載せる内容 |
| --- | --- |
| 個人レポート（パス） | 前／横／後ろ別の本数・成功数・成功率 |
| 個人レポート（ドリブル） | レガーテ／コンドゥクシオン／プロテクションごとの本数・成功率と合計 |
| 個人レポート（守備） | ボール奪取／1対1／空中戦別の本数・成功率 |
| 個人レポート（シュート） | 枠内・枠外を利き足別に、成功・失敗の数 |
| ゾーン別ヒートマップ | 30ゾーンごとの本数と成功率を色の濃さで表示。プレー種類ごとに切り替え |
| ピッチ上の矢印 | パス・ドリブルの始点ゾーン→終点ゾーンを矢印で表示（下記） |
| チーム全体の集計 | 選手一覧で本数・成功率を並べて比較（コーチ用） |
| データ書き出し | 記録を CSV で保存し、スプレッドシートで開ける |

#### 合計と成功率

パス・ドリブル・守備アクション・シュートそれぞれについて、選手別・チーム全体の両方で、合計本数・成功・失敗・成功率を出す。パスは前／横／後ろ別、ドリブルは3種類別、守備は3種類別、シュートは枠内・枠外 × 利き足別も出す。

#### ピッチ上の矢印表示

| 対象 | 表示 |
| --- | --- |
| パス成功 | 始点ゾーンから終点ゾーンへの実線の矢印 |
| パス失敗 | 始点ゾーンから終点ゾーンへの破線の矢印 |
| ドリブル | 始点ゾーンから終点ゾーンへの太い矢印 |
| 守備アクション | 表示方法は今回は決めない（ヒートマップのみ） |

選手を選んで、この図を選手ごと・試合ごとに切り替えられる。

### 4.5 スプレッドシートのレイアウト（Google スプレッドシート）

既存の見本（Numbers）と同じレイアウトを、Google スプレッドシートで作る。ツールが記録から数字を計算し、この形に自動で入力する。前半と後半は分けて表示する。見本の画面は右側と下側が切れていて、成功率の列とシュートの下の行は見えていない。大枠は見本の内容どおりにし、見えない部分は下の設計に合わせて作る。

【仮定】個人レポートは「選手1人につき、2ページ構成のスプレッドシート1つ（または同じ構成のシート2枚）」とする。

**1ページ目: スタッツ**

| ブロック | 内容 |
| --- | --- |
| レーダーチャート | 前半と後半を並べて表示。軸は「パス・ドリブル・シュート・守備」の4つ。数値は各プレーの成功率（0〜100%）。シュートは枠内の割合。前半・後半を別々のチャートにする |
| パス | 成功・失敗・成功率の表。行は前／横／後ろ／合計、列は前半・後半 |
| ドリブル | 成功・失敗・成功率の表。行はレガーテ／コンドゥクシオン／プロテクション／合計、列は前半・後半 |
| 守備 | 成功・失敗・成功率の表。行はボール奪取／1vs1／空中戦／合計、列は前半・後半 |
| シュート | 成功・失敗の表。行は枠内(R)／枠内(L)／枠外(R)／枠外(L)、列は前半・後半。成功の表には枠内、失敗の表には枠外の数を入れる |

見本では、各ブロックが「○○成功」「○○失敗」「○○成功率」の3つの表を横に並べた形になっている。

**2ページ目: ヒートマップ（矢印マップ）**

ピッチ図の上に、パスなどの矢印を描く（4.4 の矢印表示と同じ）。

**見本にあった「分析官・アシスタント・得点者・アシスト者」の欄は、今回は作らない。**

## 5. 判定ルール

### 5.1 パスの前・横・後ろ（自動判定）

始点ゾーンの列 `startCol` と終点ゾーンの列 `endCol` の差で決める。

```
diff = endCol - startCol
diff > 0  → 前（forward）
diff = 0  → 横（lateral）
diff < 0  → 後ろ（backward）
```

- 同じ列でレーンだけが違うパスは「横」。
- 自動判定が違うときは、記録者が手で直せる（上書き用のフィールドを持つ）。
- ドリブルと守備アクションの種類は、自動判定せず、記録者がボタンで選ぶ。

### 5.2 成功率

```
成功率 = 成功数 / (成功数 + 失敗数)
```

- 分母が0のときは、成功率を空欄にする（0% にはしない）。
- レーダーチャートの各軸の値は、そのプレー種類全体の成功率。

## 6. データモデル

### Team
- `id`, `name`

### Player
- `id`, `teamId`, `number`（背番号）, `name`

### Match
- `id`, `teamId`, `date`, `opponent`（対戦相手の名前。記録はしない）, `format`（`"11"` | `"8"`）, `videoUrl`（YouTube）, `playerIds`（出場選手）

### PlayEvent（1件の記録）

| フィールド | 型 | 内容 |
| --- | --- | --- |
| `id` | string | 記録の ID |
| `matchId` | string | 試合 |
| `half` | `"1H"` \| `"2H"` | 前半／後半 |
| `playerId` | string | 選手 |
| `type` | `"pass"` \| `"dribble"` \| `"defense"` \| `"shot"` | プレーの種類 |
| `subtype` | string | pass: `forward` / `lateral` / `backward`（自動判定）<br>dribble: `regate` / `conduccion` / `proteccion`<br>defense: `ball_recovery` / `one_vs_one` / `aerial`<br>shot: `on_target` / `off_target` |
| `foot` | `"R"` \| `"L"` \| null | シュートのみ（利き足） |
| `success` | boolean | 成功か失敗か（シュートは `on_target` なら true） |
| `startZone` | `{lane, col}` | 始点ゾーン（守備・シュートは発生した場所） |
| `endZone` | `{lane, col}` \| null | 終点ゾーン（パス・ドリブルのみ） |
| `passDirectionOverride` | string \| null | パスの前・横・後ろを手で直したときだけ入る |
| `videoTimeSec` | number | 記録した瞬間の YouTube の再生位置（秒） |
| `createdAt` | datetime | 記録した日時 |

【仮定】シュートのゾーンは「シュートを打った場所」を `startZone` に入れる。

## 7. 実装方針（提案）

依頼者から技術スタックの指定はない。以下は提案なので、実装前に Claude Code から依頼者へ確認してよい。

- **形態**: タブレットのブラウザで動く Web アプリ（PWA も検討）。横画面を前提にする。
- **映像再生**: YouTube IFrame Player API。`getCurrentTime()` で記録時の再生位置を取る。
- **端末内の保存**: IndexedDB または localStorage。途中で閉じても再開できること。
- **スプレッドシート連携**: Google Sheets API で、4.5 のレイアウトに自動入力する。記録のたびに転記する。
- **集計**: PlayEvent から計算する関数にまとめる（5.2 の成功率の式を1か所に置く）。
- **グラフ**: レーダーチャートは Google スプレッドシートのグラフ機能で作る。
- **矢印マップ**: スプレッドシートのセルだけでは矢印を描けない。ピッチ図と矢印を画像（SVG または PNG）として生成し、2ページ目に貼る方法を検討する。

## 8. 開発フェーズ

半自動で実際の試合に使いながら、自動化できる部分を少しずつ増やす。

1. **フェーズ1: 半自動の記録・集計** — 記録画面、選手別レポート、ヒートマップ。1試合を最後まで記録し、選手に渡せたら完了。
2. **フェーズ2: 記録の手間を減らす** — 実際に使って出た不便を直す（ボタン配置、試合をまたいだ推移など）。
3. **フェーズ3: 自動化の検証** — 実際の試合映像1〜2分で、選手・ボールの自動検出がどこまでできるか試す。
4. **フェーズ4: 部分的な自動化** — 検証で精度が出た部分だけ自動で下書きし、コーチが確認・修正する形にする。

- 自動化の順番は、パスの前・横・後ろをゾーンから自動で判定するところから始める。ドリブルと守備アクションは、まず半自動で記録し、使いながら徐々に自動化していく。
- 手持ち撮影の映像は、自動検出の精度が落ちやすい。フェーズ3の結果によっては、三脚での固定撮影も検討する。

**まず作るのはフェーズ1。** フェーズ3・4は、今回の実装範囲に含めない。

---

## 9. 今回の範囲に含めないもの

- 相手チームのプレーの記録
- 選手・ボールの自動検出（フェーズ3以降）
- 見本にあった「分析官・アシスタント・得点者・アシスト者」の欄
- 守備アクションの矢印表示
- 選手へのレポートの渡し方（リンク共有・PDF・画像などの形式は決めない。まずはスプレッドシートを共有できれば足りる）

## 10. 用語

| 用語 | 意味 |
| --- | --- |
| レガーテ（regate） | 相手を抜くドリブル |
| コンドゥクシオン（conducción） | スペースへボールを運ぶドリブル |
| プロテクション（protección） | ボールを守るドリブル |
| ボール奪取 | 相手のボールを奪う守備アクション |
| 1対1 | 1対1の局面の守備（見本の表記は「1vs1」） |
| 空中戦 | 空中のボールを競る守備アクション |
| 前・横・後ろ | パスを出した選手から見た、パスの向き |
| 枠内／枠外 | シュートが枠に行ったか。R・L は利き足 |
